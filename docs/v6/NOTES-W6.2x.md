# W6.2x — logic out of the JavaScript host (part of W6.2)

Branch `v6-w6_2x` from 14f72d3 (W6.2y). Goal: the first-party JS host (`boot.js`, `host/*.js`, `service-worker.js`)
holds only browser-API glue; decisions move to the Rust crates. No change in behaviour, pixels, exported PDF bytes,
stored data or measured performance; no new crate, tool, module split or compression. `boot.js` and
`service-worker.js` keep their logic (they run before the wasm exists; one line added to `boot.js`, see item 8).

## Left in JavaScript, and why

- **`host/fetch.js` header text parsing** — tried and reverted: sending `(name, value)` pairs instead of
  `"name: value\n"` text saved 22 bytes of JS for +390 bytes of wasm; splitting a wire format is serialization glue.
- **`host/idb.js` store-operation semantics** (put-if-absent, fill-missing-fields returning the old value, path set
  with the "max" flag, add-and-delete-at-≤0). A synchronous wasm call from inside the `onsuccess` callback would keep
  the transaction alive, so the auto-commit rule is not the obstacle. Two things are: (1) the values would have to
  round-trip through the value codec — the record → Rust direction (`Enc`) knows tags 0–14, the Rust → record
  direction (`val`) only 0–10, so a stored record holding an `ArrayBuffer`, typed array, `Map`, `Set` or `BigInt`
  could not be written back; making the codec lossless adds more JS than the ~1.2 KB of semantics removed; (2) the
  JS patches only the touched path, O(path), while a round trip copies the whole record twice, O(record), on every
  patch of every save inside the transaction — a measurable cost for no behaviour gain. Nothing is decided there
  that Rust has not said: Rust picks the operation, the mode, the paths and the flags.
- **`host/idb.js` 5.x info aggregation (FX 0x24) and dump paging (0x25)**: they run per record inside cursor
  callbacks; moving them means copying entire 5.x databases into wasm memory. The fields, the limit and the byte
  budget already come from Rust.
- **`host/platform.js` image-only filter of `files_take`**: paste/drop data is only readable during the event and the
  fallback (items → files) depends on the filter's result; moving it would send both candidate lists with handles,
  more JS than the two-line filter. **`detectApp`** and the **updater config block** are untouched (they must run
  before the wasm; the updater block is verbatim shared code).
- **`host/main.js` init config packing, `metric`, `intl`, `Reader`/`Writer`**: reads of browser values and the wire
  codec — glue.
- **`host/peer.js`** ICE gathering wait (650 ms, 70 ms after the first srflx) and the 256 KiB bulk high-water mark:
  they act inside WebRTC callbacks; passing them as parameters would cost more JS than the constants.
- **Export worker**: the PNG/JPEG sniff (`isPng`) and the "source has that page" check need the bytes and the page
  count, which only pdf-lib in the worker has; the pdf-lib calls themselves stay, in the same order.
- `boot.js` (first paint) and `service-worker.js`: not moved by rule.
